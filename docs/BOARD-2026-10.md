# The cross-platform board: Talaria against Linux on x86 and arm64 (2026-10-30)

One kernel (`3c7e9ae`, branch `arm64-port`), six workloads, fifteen test cases, two instance
families, four sides: Talaria x86, Linux x86, Talaria arm64, Linux arm64. 599 judged points
(299 on x86, 300 on arm64), every one of them an open-loop ladder point taken three times.

## How it was taken

| | x86 | arm64 |
|---|---|---|
| instance (server and generator alike) | c6i.xlarge, 4 vCPU (2 cores + HT), $0.170/h | c7g.xlarge, 4 cores, $0.145/h |
| stands | us-east-1 (postgresql, redis, nginx), ap-southeast-1 (mongodb, mysql, mongoose) | us-west-2 (postgresql, redis, nginx), eu-west-1 (mongodb, mysql, mongoose) |
| cores to the server | the passport's `SMP` (redis/nginx/mongoose 1, postgresql/mysql/mongodb 2); Linux pinned to cores 2-N | the same, except PostgreSQL: 4 cores to both sides (`SMP_ARM64=4`, `LINUX_CORES_ARM64=0-3`) |
| result directories | `bench/suite/results/ec2all-20261030-190811`, `-190832` | `bench/suite/results/ec2all-a64-20261030-190731`, `-190751` |

Every workload gets its own bring-up of four instances (Talaria server and generator, Linux
server and generator) and is torn down after. The ceiling is the median of three probes per
side; the ladder is 10/25/50/75/90 % of the SMALLER of the two ceilings, 60 s a point after a
10 s warm-up, three repeats, the median of the repeats judged. A point counts for Talaria at a
ratio < 0.95, against at > 1.05, parity between; the scoreboard drops the points below the
stand's own jitter floor and the percentiles backed by fewer than ten requests (`summary.md`
of each run). Each side drives its server with a generator on its own OS.

What this board does NOT allow:

* rows are comparable with their own Linux only. Each workload ran on its own bring-up, in its
  own region, and AWS picked up a new AL2023 image between bring-ups (six Linux AMI ids across
  twelve bring-ups). A row is not comparable with another row or with an earlier board;
* x86 against arm64 is a comparison of two stands in two regions, so read the cross-architecture
  columns as an order of magnitude and a price, not as a 5 % verdict;
* the cost is the on-demand list price in us-east-1 divided by the ceiling, the cost of a
  request with the machine fully loaded. It does not count reserved/spot prices or the fact that
  a latency SLO usually caps the usable rate below the ceiling (the top-rung table below shows
  what each side gives at 90 %).

## Conclusions

**Throughput.** On x86 Talaria's ceiling is above Linux's in all fifteen cases, 1.02x to 1.77x,
geometric mean **1.42x**. On arm64 the two are even on average (geometric mean **1.02x**, 0.81x to
1.66x): Talaria wins MySQL (1.37x / 1.66x), redis set (1.11x) and mongoose file (1.10x), loses
nginx (0.81x / 0.85x), PostgreSQL select1 (0.87x) and mongoose dyn (0.92x), and is within 6 %
on MongoDB and the rest of redis.

**Latency at light load** (the 10 % rung). Talaria's p50 is lower by ~10 % on x86 and ~7 % on
arm64 (geometric means 0.90 and 0.93): 15-20 % on redis, nginx and mongoose on both machines.
The SQL servers are the exception at low rates: on x86 MySQL's p50 is 4-9 % behind (the scoreboard's
0 / 5 / 5) and PostgreSQL is at parity; on arm64 both are at parity.

**Latency under load** (the 90 % rung) is where the board is decided. Talaria's p99 is about
half of Linux's (geometric mean 0.52 on x86, 0.60 on arm64) and its p99.9 a fifth of it on x86
(0.20) and a half on arm64 (0.54). Linux's SQL servers stall for milliseconds at the top rungs on
both machines: MySQL pk p99 2.5-2.9 ms and p99.9 ~10 ms, MySQL select1 p99 0.3-1.2 ms,
PostgreSQL on x86 p99.9 10-16 ms. No Talaria percentile up to p99.9 crosses 1 ms on any rung of
any case.

**Where Talaria still loses** (the next work, not hidden by the averages):

* arm64 nginx file at the top rung: p99 261 us / p99.9 771 us against Linux's 102 / 117, the one
  sub-millisecond tail regression on the board, together with nginx's lower ceiling on arm64;
* arm64 MongoDB insert at the top rung: p99 397 against 256 us (the scoreboard's p99.9 7 / 0 / 8);
* PostgreSQL's top-rung p99 on x86 (77 against 47 us select1, 141 against 87 us pk). Linux's
  p99 there is clean only because its tail jumps straight from p99 to 10-16 ms at p99.9, while
  ours grows smoothly with the rate; the arm64 PostgreSQL top rung's 4-6 us median gap is the
  stack lock's wait (MEASUREMENTS §10.25);
* MySQL on x86 at low rates (p50 +4-9 %), as above.

**Cost** ($ per billion requests at the ceiling, the table below):

* Talaria x86 against Linux x86: **~30 % cheaper** per request (the inverse of 1.42x);
* Talaria arm64 against Linux arm64: even on average (2 % cheaper), from 27 % cheaper on MySQL
  select1 to 23 % dearer on nginx file;
* arm64 against x86: Graviton is cheaper per request for Linux by 38 % (geometric mean), for
  Talaria by 13 %, because Talaria already takes more out of the x86 machine. Linux arm64 is on
  average 12 % cheaper than Talaria x86;
* the cheapest of the four per case: **Talaria x86** for all four redis cases and MongoDB insert,
  **Talaria arm64** for MySQL (both cases) and mongoose file, **Linux arm64** for nginx,
  PostgreSQL, mongoose dyn and MongoDB find/ping. Under a tail SLO (p99.9 < 1 ms at the
  operating rate) Linux's MySQL drops out at the top rungs on both machines and its PostgreSQL
  on x86.

**Stability.** The same kernel passed: arm64 TCG gate 419/0; x86 gate 572/1 (shmrace A/B, the
known host-load flake of the negative control) + host 22/0; the KVM stand on c7g.metal 397/0,
the large services under KVM (PostgreSQL, MariaDB, MongoDB, JVM) 15/0, the soak of 13 modes x 50
boots and the race detector of 6 modes x 96 boots with zero failed boots
(`infra/aws/logs/aarch64-20261030-190902`). All twelve board bring-ups finished with zero
workload errors.

## Reproducing

```sh
# one stand per region and per worktree (terraform's state lives in the tree)
ARCH=arm64 AWS_DEFAULT_REGION=us-west-2 STAND_DIR=$HOME/.talaria-lab/stand-w2 \
  bench/suite/run-remote-all.sh postgresql redis nginx
AWS_DEFAULT_REGION=us-east-1 STAND_DIR=$HOME/.talaria-lab/stand-e1 \
  bench/suite/run-remote-all.sh postgresql redis nginx
# ...and mongodb mysql mongoose on two more regions; then the KVM gate:
LOOPN=1 infra/aws/kvm-stand-aarch64.sh
```

The board cost about $30 of EC2: twelve bring-ups of four instances (~100 instance-hours) and
4.2 hours of c7g.metal.
