## §3. (A5) Файловая система — следующий слой

- [x] **3.1 htree (dir_index).** Индексированный каталог ЧИТАЕТСЯ спуском по
      хэшу и ДОПОЛНЯЕТСЯ с расщеплением листа и правкой узла. Формат — ext3/ext4
      (dx_root/dx_node/dx_entry), хэш half_md4/tea/legacy со знаковостью и seed
      из суперблока, сверен побайтно с `debugfs dx_hash`. Индекс с нуля не
      строим и дерево вглубь не растим: при переполнении узла каталог
      РАЗЫНДЕКСИРУЕТСЯ (снимается EXT2_INDEX_FL) — законное состояние ext2/ext4.
      Гейты: `talaria.test=htree` (3000 чужих имён находятся, 3000 своих
      добавляются, `talaria.ext2=dxcheck` сверяет КАЖДУЮ находку с полным
      перебором) + на хосте `e2fsck -fn` чист и `EXT2_INDEX_FL` цел.
- [x] **3.2 Транзакция журнала режется на части.** Было: транзакция больше
      журнала откатывала режим `journal=data` к ordered. Стало: данные едут
      порциями по ёмкости журнала (между порциями checkpoint освобождает место),
      метаданные — ПОСЛЕДНЕЙ транзакцией (после аварии на полпути они остаются
      старыми и не указывают на невосстановленные данные).
- [x] **3.3 Файловый mmap в identity-AS.** Было: окно обязано было лечь в
      непрерывный ряд слотов кэша (vaddr == phys), иначе ENODEV, а путь отката
      `mmap_unprepare` ни разу не исполнялся. Стало: страницы кэша отображаются
      по одной в окно виртуальных адресов ВНЕ identity (`paging::fmap_alloc`).
      Попутно identity-загрузчик научился читать ELF с ext2 (раньше только TFS —
      на ext2-образе нагрузка просто не находилась).
- [x] **3.4 Прогон выделения растёт с файлом** (16 → 32 → … → 256 блоков).
      Настоящий delalloc (выделение на сбросе) НЕ сделан и не будет сделан
      дёшево: слот кэша адресуется НОМЕРОМ БЛОКА, поэтому страница данных обязана
      иметь номер уже в момент записи; отложить решение — значит завести второй
      индекс (инод, блок в файле) и переучить на него пины mmap, теги журнала и
      коалесинг. Растущий прогон даёт то, ради чего delalloc и делают:
      fsbench — походов в битовую карту **33 → 7** на 512 блоков данных.

## §5. Покрытие тестами (аудит в конце сессии)

Сверены все режимы `talaria.test=` и флаги `talaria.*=` из `main.rs` с
`kernel/test.sh`. Добавлено 8 проверок:

- **htree: разындексация** — ручка `talaria.ext2=dxlimit=N` («узел полон на N
  записях») делает путь достижимым на 3000 файлах вместо десятков тысяч;
  гейт — каталог продолжает работать линейным, `e2fsck` чист, `EXT2_INDEX_FL`
  снят;
- **htree: удаление** из индексированного каталога (500 имён) — индекс остаётся
  валидным, соседние по хэшу находятся;
- **ext2 без журнала** (`talaria.ext2=nojournal`) — путь, которым ФС живёт на
  томе без `has_journal`, до сих пор в регрессе не участвовал;
- **устройство за PCIe-мостами** (root port -> upstream -> downstream) на
  НЕнулевой шине под OVMF — тот самый случай, на котором Talaria не находила
  сеть на c7i; проверяется и енумерация, и работоспособность (ext2 через NVMe
  за мостами), и то, что мосты не вытесняют устройства из таблицы;
- **счётчик реальных чтений с диска** в htree-тесте: без него замер меряет шум
  хоста (на загруженной машине те же 3200 поисков давали от 45 мс до 12 с при
  неизменных 24–45 чтениях).

Что осознанно НЕ покрыто и почему — см. `docs/TODO.md` §A0 (флаги `talaria.ena=*`
и `talaria.test=phc` требуют настоящей карты; цепочка коллизий хэша и
двухуровневый htree не строятся дешёвой конструкцией).
