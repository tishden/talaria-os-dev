# Talaria — торговый конвейер (feed→strategy→risk→TX) + zero-copy TLS

Цель: полный торговый датапас как shard-per-core конвейер (§6.2), с шифрованием
ордера на TX-стадии на месте в DMA-буфере — вместо типичного пути прикладного
TLS (OpenSSL TLS-record + копия + syscall на каждый ордер).

## Топология
```
NIC RX ─(A: feed)─a2b─▶ (B: strategy+risk) ─b2c─▶ (C: crypto+TX-prep) ─c2a─▶ NIC TX (A)
```
- **A (feed, ядро 2)**: владеет NIC. RX маркет-даты, парс минимального заголовка;
  TX зашифрованных ордеров. Пополняет пул буферов для стадий.
- **B (strategy+risk, ядро 3)**: решение (сигнал по порогу) + риск-чек (лимит
  позиции/rate); формирует plaintext ордера в буфер из пула.
- **C (crypto, ядро 4)**: AES-128-GCM на месте в буфере ордера (AES-NI +
  PCLMULQDQ), TLS-подобный record; отдаёт стадии A на TX.
- Zero-copy: между шардами ходит индекс буфера; данные в 1G-арене на месте.

## Фазы
1. **crypto.rs** — AES-128-GCM (AES-NI/PCLMULQDQ), in-place, FIPS-самотест,
   бенч стоимости шифрования ордера (~100 Б). **Делаем первым.**
2. **Многостадийный конвейер** — обобщить 2-стадийный на N стадий; торговый
   инстанс feed→strategy→crypto+TX.
3. **Tick-to-trade** — замер RX маркет-даты → TX зашифрованного ордера сквозь
   конвейер; разложение по стадиям.
4. Разложение: показать, что горячая цена TLS = AES-GCM на месте (доли мкс),
   а остальное в типичном пути — OpenSSL-оверхед, копия и syscall.

## Верификация
Крипто — против FIPS-197 тест-вектора AES-128; стоимость — PMU + TSC; tick-to-trade
покадрово.
