# Talaria — технические гэпы к полноценному тестированию

Разбивка на КОДОВЫЕ задачи (делаются и тестируются в текущем окружении QEMU/KVM)
и ТЕСТ-ПЛАН (автоматическая валидация). Цель: закрыть все технические гэпы, после
которых можно запускать полноценное тестирование (soak / latency-SLA / нагрузку).

Легенда статуса: [ ] todo, [~] в работе, [x] закрыто (с тестом).

## A. Кодовые задачи (гэпы, закрываемые в QEMU)

### A1. Корректность памяти/рантайма (блокеры длинных прогонов)
- [x] A1.1 munmap реально снимает отображение (guard очищает present + free_contig): после
      munmap доступ по vaddr -> #PF (нет UAF), фрейм переиспользуется. Тест talaria.test=uaf.
- [x] A1.2 COW-рефкаунт физфреймов (fork rc_share, cow_fault in-place при rc<=1, иначе
      копия+rc_drop). Фикс регрессии: unguard кадра при переиспользовании из free-list.
      Тест: forkp (COW-копий: N), uaf, Redis RESP-проба — все зелёные.
- [x] A1.3 Дисковые нагрузки в per-process AS (run_processes_disk): каждая в приватном
      AS с одинаковыми vaddr стека/кучи. Тест talaria.test=procdisk: два дисковых
      процесса запущены изолированно (совпадение vaddr доказывает раздельные AS).

### A2. Наблюдаемость/enforcement для валидации
- [x] A2.1 Атомарные счётчики ядра (metrics.rs): syscalls, page_faults (вкл. cow),
      frame_allocs/frames_given. Консоль `stat`; дамп после нагрузки в планировщике.
      Тест: procs -> stat: syscalls>0 (растут корректно).
- [x] A2.2 Enforcement hot-path: ячейка снимает счётчики на входе steady-state и меряет
      дельту на каждый пакет. Тест (mode=fast): «hotpath enforce ... Δsyscalls=0 Δfaults=0
      -> OK zero-syscall» на N пакетов.
- [x] A2.3 Телеметрия ячейки (telemetry.rs): pkts, p50/p99 (гистограмма log2), min/max,
      gaps (переполнение кольца), restarts (supervise), uptime. Консоль `telem` + периодич.
      serial-канал ячейки. Тест (mode=fast): валидная строка telem: с полями.

### A3. Операторка/безопасность
- [x] A3.1 Аутентификация control-plane TCP (ctlplane.rs): роут /ctl поверх kernel-httpd,
      токен в query (?token=) или `Authorization: Bearer`; верный -> 200+телеметрия, иначе
      -> 401. Тесты: ctlauth (детермин. auth-логика) + ctlplane-tcp (реальный TCP через httpd).
- [x] A3.2 Фильтр сисколов (syscall::filter_*): allowlist, вне списка -> -EPERM + счётчик +
      flight-recorder (SYSDENY). По умолчанию ВЫКЛ. Тест talaria.test=syscallfilter: getuid(102)
      вне allowlist {1,60} -> EPERM (sfilter: PASS).
- [x] A3.3 Манифест `core=` (cellman.rs): поле core (-1=не задан), парсинг core=N, доступно
      launcher/supervise для пиннинга. Тест talaria.test=manifest: core=2 распарсен и проверен.
      ОСТАТОК ЗАКРЫТ (v1.9): «доступно для пиннинга» и «пиннится» — разные вещи, и три
      сессии здесь стояло первое. Поле разбиралось и умирало: тест подтверждал РАЗБОР
      (число 2 доехало до структуры), а не то, что нить оказалась на ядре 2. Теперь
      `core=N` — ровно `pin=main:N`, то есть работающее правило раскладки (`affinity.rs`),
      и гейт проверяет, где нить оказалась (`getcpu`), а не что было разобрано.
      Грамматика раскладки: `pin=<шаблон имени нити>:<ядро|dedicated|shared>`,
      `spread=`, `balance=`, `numa=` — см. `docs/PLAN-V1.9.md` и USER-GUIDE §6.6.

### A4. Устойчивость
- [x] A4.1 Soak-режим (talaria.test=soak): 20k итераций churn аллокатора (alloc/write/
      verify/free, окно живых блоков) + верификация паттерна. Ассерт: сумма свободного
      сохранена (free_до==free_после), 0 порчи, 0 крэшей.
- [x] A4.2 Watchdog (watchdog.rs): следит за прогрессом pkts; нет прогресса STALL_LIMIT
      подряд -> stall->restart (телеметрия+flight-recorder). Тест talaria.test=watchdog:
      здоров при прогрессе, рестарт при искусственном зависании.

## B. Тест-план (автоматическая валидация, gate)

Быстрый регресс `kernel/test.sh` (49/49) + тяжёлый `kernel/validate.sh` (10/10 + B9b).

1. [x] **Функциональный регресс** (test.sh): все режимы `talaria.test=*` -> ассерт вывода. Gate: 42/42 PASS.
2. [x] **Корректность** (test.sh): munmap-UAF (uaf), COW-рефкаунт (forkp), per-process изоляция
      дисковых нагрузок (procdisk). Gate: PASS.
3. [x] **Hot-path enforcement** (test.sh): 0 сисколов/фолтов на steady-state фастпасе
      (hotpath-enforce: Δsyscalls=0 Δfaults=0). Gate: счётчики == 0.
4. [x] **Latency-SLA** (validate.sh): burst-нагрузка -> телеметрия p50/p99, замер min-латентности
      датапаса. Gate (в QEMU): min < 50µs + p50/p99 измерены. Полный tail-SLA (p99.9) на
      bare-metal (см. C) — порог фиксируется по baseline железа.
5. [x] **Soak** (validate.sh): 20k итераций churn аллокатора. Gate: 0 крэшей, сумма свободного
      сохранена (нет утечки/дрейфа). Для длинных прогонов (10–60 мин) — увеличить N/зациклить.
6. [x] **Опенсорс-совместимость** (validate.sh): busybox/lua/sqlite/quickjs/mongoose/redis
      отвечают. Gate: 6/6 PASS.
7. [x] **Безопасность** (test.sh): control-plane-auth (ctlauth/ctlplane-tcp: deny без токена,
      401), syscall-deny (syscallfilter: -EPERM). Gate: PASS.
8. [x] **Фаззинг сетевого слоя** (validate.sh): битые/частичные/случайные/oversized HTTP ->
      ядро выживает и обслуживает валидный запрос после хаоса. Gate: PASS.

## C. Вне окружения (нужно железо) — не закрывается кодом здесь
- [x] Исходящий TLS/WS-транспорт нагрузки — ЗАКРЫТ в QEMU (v0.46) через
      virtio-net/slirp (TLS в user-space: OpenSSL в бинаре нагрузки).
- [x] UEFI/ACPI-boot + реальный NIC в целевом пути — ЗАКРЫТО в v1.1 на EC2:
      Talaria грузится как AMI (`uefi-stub`, ACPI, PCIe) и работает с in-kernel
      драйверами ENA и NVMe. Датапас в v1.4 доведён до **RTT 33.6 мкс против
      43.0 у Linux-соседа** на том же участке (то есть быстрее эталона) и
      **1.28 млн пакетов/с** на передаче — рычаги: LLQ, ускоренный режим
      `accel_mode` и write-combining на окне LLQ. Разбор — POC-RESULTS §7 и
      §A1, планы — PLAN-V1.1 §4/§7 и PLAN-V1.4.
- [~] Часы / PTP / HW-таймстемпы. ЗАКРЫТА (v1.10) та часть, которая мешала
      измерениям: wall-clock больше не считается от единственной точки
      калибровки, а ДИСЦИПЛИНИРУЕТСЯ внешними часами (kvmclock под KVM, PHC ENA
      на железе) — сервопривод правит частоту, время монотонно, шаги назад
      считаются. Это то, без чего односторонние задержки (`bench/udp_owd.c`) не
      разводились на RX и TX: у гостя часы уезжали от хоста (замеряно ~36 мкс),
      а сама калибровка TSC промахивалась на 95 ppm (8,2 с/сут). Гейт
      `talaria.test=clock`.
      ОСТАЁТСЯ ОТКРЫТЫМ: (1) протокол IEEE-1588 не реализован и не планируется
      до появления стенда с grandmaster — на EC2 источник времени приходит
      админ-очередью ENA, а не пакетами 1588; (2) аппаратных меток времени на
      пакетах нет — ENA их не отдаёт, они придут вместе с in-kernel ixgbe/mlx5;
      (3) на `*.metal` kvmclock отсутствует, а PHC читается через дескриптор
      устройства, которым владеет датапас, — периодической дисциплины там пока
      нет (нужен глобальный доступ к NIC либо неблокирующее чтение PHC в две
      фазы). См. шапку `docs/TODO.md`.
- [~] Разделение общего L3 (Intel CAT). Сделано в ядре (v1.10): `llc=` в
      манифесте вешает долю кэша на ту же группу ядер, что и раскладка;
      непрерывность масок проверяется до записи в MSR, запись подтверждается
      чтением обратно, класс 0 сужается до остатка (иначе изоляция
      односторонняя). Отпечаток DMA-колец против L3 считается автоматически.
      ОСТАЁТСЯ: проверить на живом чипе — CAT не отдают гостю KVM, рабочий
      стенд только `*.metal`; там же закрывается пустая строка «C. latency +
      hog + CAT» таблицы POC-RESULTS v0.12.
- [x] Нативный bare metal — ЗАКРЫТО в v1.7 на `c6i.metal` (128 ядер, 256 ГБ,
      без гипервизора). EC2 *.metal не принимает AMI с `boot-mode uefi`
      (проверено на 6 типах), поэтому цепочка своя и BIOS-овая:
      `tools/tboot/` (stage1 72 Б + stage2 ~1.7 КБ) читает ядро с диска сам и
      уходит в `mb2_start`; GRUB не участвует. Ядро на железе: ACPI (RSDP
      находит сканированием — на BIOS-пути его не даёт никто, а без MCFG нет
      окна ECAM), PCIe через ECAM (52 моста + 307 функций), NVMe на шине `c2`,
      ext2 на живом EBS (`ext2-test: ALL OK`), PMU через `rdpmc` (IPC 1.93),
      настоящий `mwait(ring0)` (пробуждение p50 901 нс — на гостях Nitro тот же
      детект даёт `hlt+ipi`). Разбор — `docs/PLAN-V1.7.md`.
- [x] На железе SMP и сеть — ЗАКРЫТЫ (сессия 10, `docs/PLAN-V1.8.md`). На
      `c6i.metal`: `talaria.test=smp2` speedup **2.00** с `cpu=1`,
      `talaria.test=smp4` — **4.00**, нити на логических ядрах 1/2/3; ENA
      поднимается целиком (устройство отдаёт лимиты на 32 пары очередей и 132
      вектора MSI-X; драйвер поднимает ОДНУ пару — см. A6 в `docs/TODO.md`),
      LLQ 4 МБ с write-combining, адрес из VPC по DHCP. Прод-режим идёт на железе
      целиком — 15 ядер под `talaria.smp=16`, нагрузка в своём AS, сеть.
      Причины трёхсессионного молчания были не в подъёме ядер: логический номер
      ядра путался с APIC id, прошивка не назначала BAR тому, чем не грузится, а
      опрос мёртвого COM1 из тика съедал вытеснение. См. шапку `docs/TODO.md`.
- [ ] In-kernel ixgbe/mlx5 (код VFIO готов в bench/ixgbe), tail-SLA p99.9 по
      baseline железа — отдельные стенды.

## Порядок исполнения
A1 (корректность) -> A2 (наблюдаемость/enforcement) -> A4 (soak/watchdog) -> A3 (операторка/
безопасность) -> B (тест-план/гейты). ВСЕ пункты A1–A4, A3 и B1–B8 закрыты с автотестами.
Регресс test.sh — счётчик в README (v1.7: 155/155), validate.sh 10/10 (+B10) — зелёные локально и
на c6a.metal. Технические гэпы к полноценному тестированию закрыты; из раздела C закрыты UEFI-boot, реальный
NIC (ENA на EC2) и **нативный bare metal** (v1.7: своя BIOS-цепочка, ACPI, PCIe,
NVMe, ext2 на живом EBS). Остаются PTP-часы, ixgbe/mlx5, а на самом железе —
SMP и сеть (A10/A11 в шапке `docs/TODO.md`).
