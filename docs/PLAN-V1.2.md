## Порядок фаз (почему такой)

AWS-итерация стоит ~15 мин и денег, поэтому:
1. **Фаза 0 (локально): §0 — user-data как хвост cmdline.** Один AMI на все
   эксперименты вместо пересборки образа под каждую гипотезу. Делается ПЕРВОЙ,
   потому что удешевляет все последующие AWS-фазы.
2. **Фаза 1 (локально): §1 (A7) хвосты** — дёшево, снимает известные грабли
   (стек AP 128 КБ) до того, как на них наступит железная фаза.
3. **Фаза 2 (локально): §2 (A6) следующий слой ФС** — общий с EC2 код; всё
   проверяется под QEMU + e2fsck, на EBS поедет готовым.
4. **Фаза 3 (локально): §3 (A3) BIOS-загрузчик** — multiboot2 + GRUB, гейт под
   SeaBIOS локально; на *.metal поедет в железной фазе.
5. **Фаза 4 (AWS): §4** — один стенд, на нём по порядку: A2 (§8 на живом
   EBS/NVMe), A5 (клиенты СУБД), A3 на *.metal, A4 (часы), A1 (разрыв ENA).
   A1 идёт последним: он самый дорогой по времени и наименее предсказуемый.

## §0. Один AMI на все эксперименты (инфраструктура итераций)

- [x] **0.1 Хвост cmdline из EC2 user-data.** `talaria.userdata=1`: после
      подъёма netsys ядро дёргает IMDS `/latest/user-data` и ПРИКЛЕИВАЕТ
      содержимое к cmdline. Требует: cmdline в статическом буфере (сейчас
      `&'static str` прямо на страницу start_info), идемпотентный `netsys::init`
      (ранний подъём + повторный вызов из режима — no-op).
      Ограничение (задокументировать): режим `mode=fast` (ячейка zero-syscall на
      AP забирает карту себе) из user-data не выбирается — только из `talaria.cfg`.
      Гейт: мок IMDS в `test.sh` отдаёт user-data, ассерт «параметр из user-data
      применён».

## §1. (A7) Хвосты, замеченные попутно

- [x] **1.1 `Nic` по ссылке, а не по значению.** Сейчас карта едет
      `nic_handoff_take() -> run_datapath -> run_cell -> NicQ::new` тремя-четырьмя
      копиями по стеку AP (из-за чего стек раздут до 128 КБ). Карту — в статику,
      по путям — `&'static mut Nic`. Гейт: стек AP обратно на 32 КБ, регресс
      сетевых режимов (fast/httpd/smoltcp/userver) зелёный.
- [x] **1.2 `talaria.netidle=1` для virtio.** Было только у ENA; теперь спим на
      слове (flags,idx) used-кольца приёма. Гейт взят с запасом: проходов стека
      на оборот 8 000 000 -> 4 551, эхо не теряется.
- [~] **1.3 `tsync` FAIL на c6a.metal.** Артефакты (`tsynctest.dyn`,
      `fiberbench`) были собраны из кода ДО правок v0.53b — пересобраны.
      Сам FAIL воспроизводится только на EPYC: перенесено.
- [~] **1.4 Флейк `talaria.test=connect` (DNS).** НЕ воспроизвёлся: 48 прогонов
      (24 в покое + 24 под десятикратной нагрузкой CPU) — 48/48 зелёных.
      Вслепую не чинил; закрыт самый вероятный молчаливый путь к симптому
      (EMFILE пула сокетов и отказ bind теперь печатаются).

## §2. (A6) Файловая система — следующий слой

- [x] **2.1 Множественно-ассоциативный блочный кэш.** Сейчас прямого
      отображения (`bn % NCH`) + 64 «вытесненных» слота под пины. Сделать
      N-канальным с LRU внутри набора: снимает конфликтные промахи (таблица
      инодов и данные файла бьются в один слот) и убирает костыль NDISP.
- [x] **2.2 Файловое отображение без требования непрерывного окна.** Сейчас
      `mmap_prepare` честно отдаёт ENODEV, если блоки файла разбросаны. Страницы
      кэша можно отображать ПОСТРАНИЧНО (таблица страниц и так per-page) —
      требование непрерывности снимается совсем.
- [x] **2.3 Запись журнала одной пачкой.** Сейчас descriptor уходит отдельным
      `blk_write`, копии — отдельным `blk_write_many`. Собрать всё в один запрос.
- [x] **2.4 Отложенное/пакетное выделение блоков.** Сейчас `alloc_block` на
      КАЖДЫЙ блок файла + `sb_flush` на каждое выделение. Резервировать за инодом
      непрерывный прогон блоков (окно преаллокации) и обновлять суперблок один
      раз на прогон: меньше метаданных, файлы ложатся подряд (что заодно кормит
      2.2 и коалесинг §8.2).
- [x] **2.5 Журналирование ДАННЫХ как опция.** Сейчас только ordered.
      `talaria.ext2=journal=data`: данные идут в транзакцию вместе с
      метаданными. Гейт: crash-consistency тест с данными.

## §3. (A3) BIOS-загрузчик — нативный bare metal

- [x] **3.1 multiboot2-заголовок в ядре.** Второй вход рядом с PVH: `eax` =
      `0x36d76289`, `ebx` = multiboot2-info. Карта памяти (tag 6) и cmdline
      (tag 1) переводятся в тот же `hvm_start_info`, который уже ест `mem::init`
      — дальше ядро не отличает загрузчиков.
- [x] **3.2 GRUB в образе (`tools/mk-ami.sh --bios`).** MBR + BIOS boot
      partition + `grub.cfg` с `multiboot2 /talaria` и cmdline. Гейт: тот же
      смоук-набор под QEMU БЕЗ `-kernel` и БЕЗ OVMF (SeaBIOS, `-drive`).
- [x] **3.3 Гибридный образ.** Один диск, грузящийся и по UEFI (ESP), и по BIOS
      (MBR+GRUB) — чтобы не держать два артефакта.

      Порядок из TODO был строго:

      (3) только потом гипотеза про вычитку RX-дескрипторов.
      Гейт: RTT против Linux-соседа не хуже 1.5x. **Гейт может не взяться —
