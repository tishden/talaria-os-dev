# Talaria — оптимизация работы с оперативной памятью

Рамка: текущий датапас (rx→tx 30–60 нс, 98% <100 нс) уже memory-light —
рабочий набор крошечный. Оптимизация памяти критична при **большом состоянии**
ячейки (order book по тысячам инструментов, тиковый стор, фичи): тогда
доминируют TLB, LLC и NUMA. Приоритет зависит от профиля нагрузки.

## Уже сделано
1G-hugepages под DMA-арену, prefault, mlock, пул буферов + free-list, ноль
аллокаций на hot path, физадресация через pagemap, инвариант page-faults=0,
zero-copy TX (обмен буферами).

## Дорожная карта (по убыванию отдачи)

1. **PMU-счётчики в телеметрию** (§6.10) — dTLB-load-misses, LLC-load-misses,
   uncore memory-bandwidth через rdpmc (userspace, без syscall — ячейка остаётся
   syscall-free). Без измерения оптимизация вслепую. **Делаем первым.**
2. **Prefetch на датапасе** — __builtin_prefetch следующего RX-дескриптора и
   заголовка следующего буфера; в паре с адаптивным батчингом прячет DRAM.
3. **Синтетический большой стейт** — использовать synth pointer-chase (v0.12),
   чтобы память стала узким местом и появился объект оптимизации.
4. **1G-маппинг всего стейта ячейки** (код/стек/кольца/буферы/стейт), тождеств.
   отображение — TLB-reach с 6 МБ (4К) до 1536 ГБ; page-walk'и на hot path
   исчезают. Полноценно — в no_std/bare-metal ячейке; в userspace-PoC — весь
   датапас-стейт в 1G-арену.
5. **NUMA-локальность** — поле numa_node в манифесте; mbind памяти шарда на
   локальный узел; NIC DMA в буферы своего сокета; ноль cross-node на hot path
   (~100 нс промах через UPI).
6. **LLC (CAT) + memory-bandwidth (MBA)** — партиционирование L3 (resctrl-код
   готов, v0.8/0.11) + MBA-троттлинг DRAM-полосы batch-ячейки. Манифест:
   llc_mask (есть) + mba_percent (добавить). Нужен хост с resctrl (не AL2023).
7. **DDIO-осознанное кольцо RX** — размер RX-кольца в пределах DDIO-way, иначе
   «leaky DMA» вымывает горячие данные из L3; на bare-metal — DDIO-way через CAT.
8. **Cache-conscious layout** — alignas(64) на кольцах и per-shard счётчиках
   (ноль false-sharing), SoA для горячих полей, hot/cold split, скользящее окно
   order book (компактный горячий диапазон уровней).
9. **Non-temporal stores (MOVNT)** для тикового стора/append-log — потоковая
   запись мимо кэша, не загрязняет L3. ZNS/NVMe append снизу.
10. **Zero-copy между шардами** — передача буфера по указателю через SPSC-кольцо
    в едином адресном пространстве; TLS шифруется на месте в отправном буфере.

## Верификация
Каждый пункт проверяется PMU-счётчиками из п.1 (dTLB/LLC-misses на пакет,
memory-bandwidth) — как у Rigtorp. perf_event_paranoid=-1 уже выставлен.
