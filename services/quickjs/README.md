# QuickJS on Talaria — a JavaScript engine in ring 3

Unmodified [QuickJS-ng](https://github.com/quickjs-ng/quickjs) (a fork of
Fabrice Bellard's engine), built statically against musl (0x10000000), runs
`demo.js` **in ring 3 on the Talaria kernel**. It shows a complete JS runtime
(parser, bytecode VM, GC) on this kernel:

```

sorted: [0,1,2,3,5,6,7,8,9,10]

string: TALARIA len=7 rev=airalat

QuickJS OK on Talaria
```

## Build and run

```
git clone --depth 1 https://github.com/quickjs-ng/quickjs.git src
docker run --rm -v "$PWD":/w -w /w talaria-musl sh -c \
  'musl-gcc -O2 -static -no-pie -Wl,-Ttext-segment=0x10000000 -D_GNU_SOURCE -Isrc -o qjs \
     src/qjs.c src/quickjs.c src/libregexp.c src/libunicode.c src/dtoa.c src/quickjs-libc.c stub.c -lm'
cp qjs qjs_bin && python3 mkdisk.py disk-quickjs.img
services/quickjs/run.sh
```

`stub.c` stubs out the generated bytecode of the REPL (`qjsc_repl`/`qjsc_standalone`),
which is not needed to run a script. Kernel mode: `talaria.mode=quickjs`.

This workload needed readlink (89) with `/proc/self/fd/N` support and EINVAL for
existing regular files (musl's `realpath`), and readlinkat (267).
